文件重写回单文件，导致主文件体积重新变大。当前四个待拆文件：

### 1.2 目标

**把单体文件按领域职责重构为多模块，而不是按行数机械切分。**

验收有两条，都必须满足：

1. **行数**：主文件 ≤ 上游行数 × 0.6（计划文档 §2.2 硬性规则）
2. **领域**：每个新模块必须对应一个可命名的职责，不允许出现「第 N 段」这类
   无语义模块

## 2 架构原则

### 2.1 三条依据

本项目的拆分方式参考两项外部研究：

- **ES 模块即单例**（Keegan Watkins《Stop treating your ES modules like junk
  drawers》）：模块级可变状态不可测试、不可重置。应把状态收敛为显式对象，
  并提供读取与重置入口，而不是散落在模块作用域里。
- **组合优于继承、单一所有者**（thepineapple.express 的 Three.js 无框架架构）：
  根对象以 `readonly` 字段持有子系统；**子系统之间不互相引用**，通信经由
  根对象；避免模块级可变变量。

### 2.2 落地纪律

| 场景               | 做法                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------ |
| 只读的闭包状态     | 子模块声明模块级 `let`，宿主注入 `get_x: () => x`，正文用 `_get_x()`                       |
| **可变的闭包状态** | 必须 `get`/`set` **成对**注入，否则两边赋值互不可见                                        |
| 宿主内的函数       | 直接注入 `fn: fn`，子模块 `let _fn`                                                        |
| 跨模块的常量/工具  | 直接 `import`，不走注入                                                                    |
| 同名局部变量       | **不得批量替换**。函数内 `const layout = state.layout` 保持局部，只对跨函数共享的用 getter |
| 循环依赖           | 消除：把被依赖方上移，或改单向 import                                                      |

### 2.3 门面 re-export（血泪教训，已踩 4 次）

搬走一个 `export function` 后，**必须在源文件补 re-export**：

```js
export { rawUrl, texCacheKey, parentModelPath } from './mcv/paths.js'
```

否则：

- `test/unit/*` 通过主文件 import 会拿到 `undefined` → 单测失败
- 浏览器会报 `does not provide an export named ...` → 页面异常

**执行顺序**：搬走 → 加 re-export → 立刻跑单测确认 → 再继续下一步。

## 4 执行流程

每个文件走同一套流程，**不允许跳步**：

```
1. 跑基线验证（单测+冒烟+浏览器），确认干净起点
2. 用领域分析脚本定位候选（按职责，不按行数）
3. 抽取一个模块 → 语法检查
4. 源文件删除该段 → 加 import + setHooks 注入
5. 补门面 re-export（若有 export）
6. 引用审计 audit-web-refs.mjs
7. 单测 + 冒烟 + 浏览器 三项全过
8. 格式化 prettier + format:check
9. 提交（Conventional Commits）→ 推送
10. 下一个模块，重复 3-9
```

### 4.1 验证命令（缺一不可）

```bash
node scripts/audit-web-refs.mjs      # 跨模块缺失引用
node scripts/run-unit-tests.mjs      # 单测（应为 755 pass / 0 fail）
node test/smoke/run.mjs              # 冒烟（29 通过 0 失败）
node scripts/browser-e2e.mjs         # 浏览器（9 步 / 0 / 0 / 0）
npm run format:check                 # 格式
npx eslint .                         # 0 errors
```

### 4.2 已知 flaky（复跑即过，不算回归）

- `test/unit/model-thumb-dirs.test.js`：缩略图目录时序（已修 invalidate 竞态）

## 5 常见错误与对策

| 症状                                       | 根因                               | 对策                                        |
| ------------------------------------------ | ---------------------------------- | ------------------------------------------- |
| `does not provide an export named X`       | 漏门面 re-export                   | 源文件加 `export { X } from './子模块'`     |
| `Identifier 'X' has already been declared` | 子模块重复 import 或 import 行重复 | 去重                                        |
| `const _get_x() = ...` 语法错误            | 同名局部变量被批量替换             | 函数内保持局部变量，只对跨函数共享用 getter |
| `async export function`                    | 加 export 的顺序错                 | 应为 `export async function`                |
| `hlFace is not defined`                    | 可变状态只注入了 getter            | 补 `set_` 成对                              |
| 浏览器 0 错误但引用审计报缺失              | 子模块引用了尚未注入的符号         | 补 import 或补 hook                         |
| hooks 注入逗号缺失                         | 脚本拼接时漏逗号                   | 注入后必跑 `node --check`                   |

### 5.1 三次失败实录（2026-10-31，`mc-model-viewer.js`）

这三组尝试**全部失败并已 `git checkout` 回退**，记录在此避免重蹈：

#### 失败一：`mcv/tex-refs.js`（单测挂 4 个）

搬走 `writeMcTexRef` / `texUrlToRef` / `expandTextureAliases` /
`texPathForRef` / `packRelToMcRef` / `resolveTextureRef`（共 89 行）。

**症状**：`断链别名回退`、`writeMcTexRef`、`buildMcLayout`、
`resolveTextureRef` 四个用例失败。

**根因**：这六个函数依赖 `textureAssetPath` 与 `isSpecialTexPath`。原本用
`setHooks` 注入，但**单测直接 import 子模块并调用 `writeMcTexRef`，
此时宿主的 `setHooks` 还没执行，`_textureAssetPath` 仍是
`(...a) => undefined` 的占位函数**，于是返回 undefined 而非真实路径。

**教训**：**被单测直接调用的函数，其依赖必须能在模块加载时解析**——
要么 `import`（会成环时改为主文件先定义、子模块后导入），
要么把依赖一并移入子模块。**运行时 hook 注入只适用于"宿主初始化后才使用"
的函数（如 UI 回调），不适用于纯函数。**

#### 失败二：把 `isSpecialTexPath` / `textureAssetPath` 一并移入（单测挂 256 个）

试图让 `tex-refs.js` 自包含，把这两个函数从主文件删掉。

**症状**：从 4 个失败扩大到 **256 个失败**。

**根因**：主文件自身有 **40+ 处**仍在调用 `isSpecialTexPath`
（L786/983/1022/1062/1133…），删掉定义后全文件 `ReferenceError`。
`node-canvas.js` 也依赖它。

**教训**：**搬运一个被广泛引用的私有函数前，先数引用次数**
（`grep -c`）。引用 > 5 次的基本应视为"公共工具"，只搬调用者、不搬它。

#### 失败三：`mcv/layouts.js`（单测挂 256 个）

搬走 `buildMcLayout` / `buildBbLayout` / `expandElementFaces` / `parseVec3` /
`parseUv` / `normFaceRotation`，**并把常量 `MAX_ITEM_DEF_REFS` /
`HIDDEN_MAT` / `MAT_INDEX` 一起搬走**。

**症状**：256 个失败。

**根因**：这三个常量在主文件还有其他使用者（引用 2/3/5 次）。常量被搬走后，
主文件里变成"引用存在、定义消失"。同时脚本把常量的**声明**
`const MAX_ITEM_DEF_REFS = 16` 误改成了 `const _get_MAX_ITEM_DEF_REFS() = 16`
（把常量当成了外部注入项）。

**教训**：

- **常量声明绝不能走 getter 注入**。常量要么留在主文件、要么搬走并让所有
  使用者 import，不存在"注入"这条路（它不是可变的）。
- 识别"模块内自有声明"与"需注入的外部符号"时，不能只靠正则扫大写标识符；
  **必须先建立本文件顶层声明表，凡在表内的就是自有符号**。

### 5.2 从失败中得出的操作纪律（补充到 §4 流程）

在 §4 的「步骤 2」与「步骤 3」之间，**必须插入一步依赖体检**：

```bash
# 1) 待搬函数用到的每个外部符号，逐一确认
node -e "统计待搬函数调用的标识符"   # 区分 已import / 本文件其他函数 / 常量

# 2) 对每个"本文件其他函数"，数它在主文件被引用多少次
grep -c "该函数名" web/src/目标文件.js
#    > 5 次 → 视为公共工具，不搬它，只搬调用者并 import 它
#    ≤ 5 次 → 可一并搬入子模块

# 3) 对每个常量，判断它是"本文件声明"还是"外部 import"
#    本文件声明 → 留在主文件，子模块 import 或通过参数传入
#    （没有 getter 注入这条路）
```

**判定表**：

| 符号类别                             | 处理方式                                              |
| ------------------------------------ | ----------------------------------------------------- |
| 已 import 的包/工具                  | 子模块直接 import                                     |
| 本文件其他**函数**，引用 ≤5 次       | 一并搬入子模块                                        |
| 本文件其他**函数**，引用 >5 次       | 留在主文件，子模块 import（必要时调整定义顺序避免环） |
| 本文件**常量**                       | 留在主文件；子模块 import                             |
| 闭包/可变状态（`let`，运行时被赋值） | `get`/`set` 成对注入                                  |
| 宿主初始化后才用的回调               | 直接注入                                              |

**核心原则**：**能 import 就不注入**。注入只用于"运行时才有值"的东西。
